# Release / Evidence Note: CLI plan and evidence helpers

## Summary

Adds small `osc plan new` and `osc evidence new` helpers so the first-plan and evidence-note path is less manual while preserving explicit human-filled TODO prompts, acceptance criteria, verification, and shell/script fallbacks.

## Traceability

- Plan: `.osc/plans/done/044-cli-friction-reduction.md`
- Branch: `cli/plan-evidence-helpers`
- PR: `#52` — https://github.com/graphanov/open-scaffold/pull/52
- Kanban: `t_49065bef`
- Related docs: `README.md`, `docs/MINIMUM_VIABLE_SCAFFOLD.md`, `docs/WORKFLOW.md`

## Outcome

- Added `osc plan new <slug> --stage active|backlog|blocked`.
- Added `osc evidence new <slug>`.
- Plan skeletons include the required plan sections and explicit TODO prompts instead of invented acceptance criteria.
- Evidence skeletons create `.osc/releases/<date>-<slug>.md` with Summary, Traceability, Verification, Outcome, and Follow-up sections.
- Helper commands reject duplicate files, invalid plan stages, unsafe slugs/path traversal, and missing scaffold roots.
- Missing-root tests explicitly use `/tmp` for no-root fixtures so an environment `TMPDIR` pointing inside a scaffold root cannot mask the error path.
- README, minimum-scaffold docs, workflow docs, and downstream generated templates now mention the helpers while keeping shell/script fallbacks.
- Out of scope: `osc amend`, `osc close`, runtime launch behavior, wizard behavior, autogenerated acceptance criteria, merge, and publish.
