## Date

## Learning

The owner corrected the positioning: Open Scaffold must not read as software-only. The current README/mission wording says “AI-assisted software” and several docs center code/development too early. The product category should be broader: a repo-native work record for any AI-assisted work that deserves durable plans, handoffs, evidence, approvals, and lessons. Software remains an important first proof path, but not the category boundary.

## New direction

Broaden the public positioning from “AI-assisted software” to “AI-assisted work.” Current public docs should lead with project/work language and only use software/code examples where a specific feature truly depends on repositories, CLI, GitHub PRs, tests, or package workflows.

## Impact on acceptance criteria

- AC1 expands from README/software positioning to README/general AI-assisted work positioning.
- AC2 expands from mission/software wording to mission/general work wording while preserving the concrete software implementation path.
- AC3 expands from glossary/comparison cleanup to a public-doc terminology pass that avoids making software the product category.
- AC6 adds an explicit regression: first-touch positioning docs must not define Open Scaffold as only “AI-assisted software.”
