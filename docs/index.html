open-scaffold
README · Stability · Changelog · GitHub

AI work needs a harness.

Open Scaffold clarifies, plans, gates, and records AI-assisted work in your repo — four verbs drive the loop, and every attempt leaves a receipt your team can review.

Kill the session mid-task. Any agent or operator can resume bounded work straight from the repo after total chat-context loss — no re-explaining. See the resume demo fixture and the resume walkthrough.

First command

Guided start in a new or existing repository.

npx open-scaffold@latest first-run

Three questions produce the minimum work record and the exact next commands.

ProblemAI work disappears into chat, retries loop blind, and nobody can review what happened.
AudienceDevelopers and teams using agents for work that must survive the session.
Method$interview, $plan, $work, $team — a gated loop whose record lives in the repo.
BoundaryExecution is explicit: adapter + spawn authority + human gates. Humans own merge and release.

Solo developer

Resume work after a week away. The mission, active plan, verification commands, and latest evidence are in the repository instead of an old chat.

Team PR review

Attach intent, constraints, acceptance criteria, tests, and review state to the branch so reviewers see why the change exists.

Client or audit-sensitive delivery

Keep a lightweight trail of what was requested, what was produced, what passed, and what humans approved.

What you can rely on today

The work loop and its record are stable: MISSION.md, plan folders with acceptance criteria, amendments, run records with status/events/receipts, evidence notes, osc verify, and the harness grammar $interview / $plan / $work / $team. Runtime launch is explicit and gated: an adapter id, spawn authority, and human gates.

One page holds the full maturity contract — stable, experimental, future, and the honest limits: the stability page.
