open-scaffold
README · Stability · Changelog · GitHub

AI work needs a repo record.

Open Scaffold keeps the goal, plan, handoff package, evidence, approval trail, and lessons from repeated AI-assisted attempts in files your team can review.

Any agent or operator can resume bounded work straight from the repo after total chat-context loss — no re-explaining needed. See the resume demo fixture and the resume walkthrough.

First command

Start small in a new or existing repository.

npx open-scaffold init --tier min --target .

Use --tier standard for README, roadmap, docs, and agent instructions.

ProblemAI work disappears into chat, terminals, and memory.
AudienceDevelopers and teams using agents for work that must be reviewed later.
MethodMission, plans, run packets, evidence, and close records live in the repo.
BoundaryAgents do the work. Open Scaffold records and verifies the work.

Solo developer

Resume work after a week away. The mission, active plan, verification commands, and latest evidence are in the repository instead of an old chat.

Team PR review

Attach intent, constraints, acceptance criteria, tests, and review state to the branch so reviewers see why the change exists.

Client or audit-sensitive delivery

Keep a lightweight trail of what was requested, what was produced, what passed, and what humans approved.

Current contract

Open Scaffold is on a pre-1.0 hardening line: usable for real work records, but still honest that the adoption path and runtime boundaries are evolving. The stable-enough core is the repo protocol: MISSION.md, ROADMAP.md, plan folders, the Status + seven content-heading plan schema, amendments, evidence notes, verify.sh, and day-two CLI helpers such as osc plan, osc amend, osc close, osc evidence, osc verify, osc compare, and osc status.

Experimental surfaces include runtime profiles, osc work --dry-run, osc dispatch, MCP, cockpit webhooks, local task database helpers, dashboards, runtime packages, and native spawning research.
